## Verified @mastra/core API surface (1.63.2) — found 2 real bugs

Technique that unblocked verification without installing anything: `npm pack @mastra/core@1.63.2` into `/tmp`, `tar xzf`, then read `dist/**/*.d.ts`. Avoids the broken pnpm store entirely. Reusable for any package.

Confirmed: `Agent` @ `@mastra/core/agent` (also re-exported from root); `createTool` @ `@mastra/core/tools`; `LocalSandbox` + `Workspace` @ `@mastra/core/workspace` (there is NO `@mastra/core/sandbox` subpath — 86 total exports). `new Workspace({ sandbox: new LocalSandbox(opts) })` is correct.

**Bugs found and fixed in `mastra/runtime.ts`:**
1. `sendSignal(signal, target)` takes TWO positional args, not one merged object. `signal.type` must be a delivery category (`user|state|reactive|notification` + legacy `user-message|system-reminder`), NOT a domain string — put the Papyrus event type in `tagName`/`attributes`. `target` is a union: `{runId}` OR `{resourceId, threadId}` — threadId alone is insufficient. Result has an **`accepted` promise** resolving to `wake|deliver|persist|discard|blocked`; only wake/deliver/persist mean delivery. **Acking on `discard`/`blocked` would silently delete evidence** — the exact failure the outbox exists to prevent. Now throws so the row retries.
2. **`model` is a REQUIRED Agent option** (also `id`, `name`, `instructions`). No model => don't build the agent. Added `PAPYRUS_INVESTIGATION_MODEL` env var; absent => agent unregistered, signals accumulate durably. Also: `memory` expects a `MastraMemory`, NOT a store — LibSQLStore goes on `new Mastra({ storage })`, which is what actually gives threads durability.
